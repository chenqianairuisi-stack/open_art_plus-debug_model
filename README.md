# open_art_plus-debug_model
这里主要是开源全局定位摄像头的代码

在五月份前的主控移动速度--线性加速度200cm/s²之下的，QVGA是完全够用的，但是到了后期，为了跟上移动速度，提高坐标更新效率，所以把帧率降低到了QQVGA。

从直观画面上，很容易可以看出QVGA的全局锁定在QQVGA状态下根本用不了。

反应现象为：框选精度不够，误判过多，失误率大，在绿色进去暗区时候，锁定框会自动贴合到高亮处的黄色色块。所以多做了几步处理，下面就说一下主要的区别点，具体的，可以通过代码找出:
                                     QQVGA                                  QVGA
                                     
1.单像素对应实际距离           约 2 cm/px，精度较低	                约 1 cm/px，精度较高

2.地图采样 ROI	                   每格 6×6 像素	                     每格 12×12 像素

3.地图颜色识别	             使用 ROI 的 LAB 平均值判断	           统计各颜色命中的像素数量

4.地图识别特点	            运算快，但容易受背景混色影响	         运算量较大，但抗混色能力更强

5.小车中心计算	          优先使用 min_corners() 四角平均	     直接使用 blob 质心 b.cx()/b.cy()

6.小车位置滤波	         匀速 Kalman 滤波，并带异常跳点门限	           简单的一阶平滑滤波

7.静止状态处理	             静止时最多进行 5 帧中心平均	             没有独立的静止多帧平均

8.青色兜底定位	           有"绿+青"检测失败时单独搜索青色	           没有单独的青色兜底定位

9.小车候选筛选	           更严格，冷启动时优先要求包含青色	       直接按尺寸、面积、填充率筛选

10.绿/青合并距离	             TRACK_MERGE_MARGIN = 1	               TRACK_MERGE_MARGIN = 6

11.车身尺寸限制	            最大约 15 像素，比例限制更严格	     最大约 64 像素，允许部分车身被遮挡

12.显示框	                  固定 11×11 像素，并带迟滞防抖	         直接显示 blob 的真实外接矩形

13.丢车搜索范围	            22 像素，重新捕获最大 41 像素	         44 像素，重新捕获最大 82 像素

14.绿色颜色阈值	         针对低分辨率降采样后颜色变暗进行放宽	     使用适配高分辨率的另一套阈值

15.位姿标定	          地图四角和位姿四角分开定义，可额外做轴向标定	    地图和位姿共用一套四角

16.航向角计算	            公式相同，但航向 ROI 按低分辨率设置	   公式相同，航向 ROI 按高分辨率设置

17.计算负担	                     较低，运行速度更快	              较高，但获得的图像和地图精度更好

18.适合场景	               追求帧率、低延迟，允许精度较低	          追求定位精度和地图识别稳定性
